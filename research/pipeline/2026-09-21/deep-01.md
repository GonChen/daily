# 2026-09-21 deep-01：基线会过期——复现边界的四种失效

问题：本周六条独立一手证据指向同一件事：性能与正确性结论只在生成条件下成立，跨条件继承基线会付出真实代价。

| 失效维度 | 事件 | 触发条件 | 后果 | 处置 |
|---|---|---|---|---|
| 构建 | Ollama 跨请求提示词泄漏（llama.cpp #29092 → ollama #18528） | 同一上游源码，Ollama 0.34.1 打包版 vs 官方 master，Strix Halo/HIP + fused Gated DeltaNet | 上一请求文档逐字进入下一请求补全（temperature 0 确定性复现），隐私级 | 三方 A/B（源码 commit × ROCm runtime × 量化）指认打包构建；上游赦免 |
| 版本 | vLLM #57413：七月清理 #49244 把 `--max-num-partial-prefills` 当死配置删除 | V1 引擎 + 100k–180k token 长提示 + TP4×4×B200 | 短请求被 7–12 调度步长 prefill 队头阻塞，TTFT 尾延迟；两处独立生产证据 | 社区 rebase 复活 PR #57427，对拉生产流量验证 |
| 硬件 | vLLM #49435（SM100 fp8_ds_mla cache scales）、#50455（gfx950/gfx942 logits 塌陷） | DSv4/DSv4.1 在 B200 与 AMD MI300+/MI350 级 | 修复前非 Hopper 平台的 FP8 MLA 精度结果不可作对照 | 结果级修复合入，数值基线按硬件重置 |
| 并发 | vLLM #57604：MegaMoE 8-token staging tile 在小批量反优化 | <64 token 小批量（16 token 内核 2.400→2.752 µs 回归） | 低并发无收益甚至回归；8192 token 才有 5.4× | 显式门控：≥64 token 才启用新 tile |

共性结论：
1. **"同代码"不等于"同行为"**：Ollama 事件说明构建管道（补丁、fused-op resolver、依赖版本）本身就是行为变量；对照实验必须钉住二进制，不只钉住 commit。
2. **清理也是变更**：#57413 的死配置删除与 v0.5.20 的默认翻转（`/v1/responses` 400、CUDA 12 退役）都是"没有新功能的破坏性变化"——升级清单要包含"消失的东西"。
3. **数值基线有硬件时效**：#49435/#50455 修复前，V4.1 在非 Hopper 上的复现不成立；跨硬件对比必须注明修复版本。
4. **门控优于全局开关**：#57604 用 ≥64 token 阈值保留两端最优；#57421 则是反面——收益与风险都存在但机理未明，只能靠双基线披露。
5. 证伪条件：若 #57427 被维护者以"V1 调度器设计如此"拒绝，#57413 应降级为配置争议；若 Ollama 侧证明根因在其下游依赖而非打包，则"构建变量"叙事收窄。本页未声称独立复现。
