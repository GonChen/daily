Blackwell 推理优化同时推进快路径与安全回退

TensorRT‑LLM 的 DSpark 融合只在 SM100/SM103 启用，其他硬件保留 PyTorch fallback；同一批主线改动还为 KV cache rebalance 补齐 TP、CP、PP 与 attention‑DP 下的协调逻辑。

深度解读

three working theses
01 项目级担保02 开放权重的边界03 快路径与控制面

01｜1,050 亿美元上限把 AI 工厂的尾部风险具体化了

上周“动员超过 5,000 亿美元资本”的 MOU 仍是平台层意向；本周 SEC 文件则落到一个首期 4.25GW、20 年租期、2028 年上线的具体项目。担保只有在 OpenAI 信用事件和资产处置不足时才触发，且 OpenAI 对 NVIDIA 有偿还义务，因此不能把上限当作支出或损失。

但合同结构改变了分析框架：NVIDIA 不再只赚取芯片毛利，也可能用自身信用为客户、园区和 GPU 残值搭桥。未来应把担保余额、客户集中度、替代租户池、硬件代际折旧和可再部署性放进同一张风险表。

观察链：4.25GW 建设进度 → OpenAI 租金/信用 → 利用率与现金流 → 替代租赁/资产处置 → NVIDIA 实际付款 → OpenAI 偿还。最大金额只描述尾部，不描述概率。

02｜“开放权重”不是一个统一的采购规格

Qwen3.8 是很好的反例：同一代名下，2.4T‑A95B 是纯文本、必须 thinking、专用许可；27B 是视觉语言、可关闭 thinking、Apache 2.0。Hosted Qwen3.8‑Max 又有自己的模态与服务能力。把三者只写成“Qwen3.8 已开源”，会同时误导合规、容量和应用设计。

部署清单：权重可得性 → 许可证/使用限制 → 模态 → thinking 协议 → context/KV 成本 → vLLM/SGLang 版本 → 量化与硬件路径 → 独立质量复现。

03｜推理加速的收益，越来越取决于控制面是否诚实

DSpark 融合的 4.63× 是一个优秀快路径信号，但只覆盖 B200 微基准与特定形状；真实系统还要正确选择硬件 fallback、维护 speculative target/draft KV，并在多并行域中一致地重平衡。

KVCacheManagerV2 的例子更有警示性：1.5% 的 warmup dummy 因平方统计支配全部容量估计，足以诱发 171GB/rank 的错误搬运决策。没有可信 workload 采样，再快的搬运也只是在更快地做错事。

验收提示：同时报告端到端 goodput、P99、接受率、显存/网络搬运、fallback 命中率、准确率与测试矩阵；微基准只回答“这个 kernel 能多快”。
