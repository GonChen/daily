Executive readout

推理优化必须通过三道审计：它在完整工作流里剩多少收益、首次使用要付多少调优、以及请求有没有被重复、丢失或错解。

FlashInfer 同日合入的两个 PR 展示了两种常被省略的差额：block-sparse attention 在局部 API 测量里约 1.90×，但 FastWan 完整生成只约 1.016×；W4A16 dense GEMM 平均快约 2.98%，却把冷启动 autotune profile time 提高 2.12×。Agent 侧，Claude Code 修补预算/代理重试，SGLang 修补静默掉工具调用。性能、成本和执行正确性需要是同一条请求链上的指标。

深度解读

from microseconds to audited requests
Deep dive 01

局部更快，必须先赢过端到端和首次使用成本。

kernel/API → 完整工作流 → cache miss → 服务 SLO

FlashInfer #4593 的对照排除了最常见的误读：16 行 canonical attention 的 1.902×，并不会自然传递到 FastWan 的完整 61 帧生成；该口径只剩 1.015714×。#4686 则补上了生命周期一端：热路径约 2.98% 的几何均速，伴随 2.12×的冷调优 profile time。

因此，部署决策不能以最快 microbenchmark 排序。应以真实形状分布、cache 命中、扩缩容频率、p50/p99、成本和输出一致性测完整请求；若 p95 首次请求没有收益，就不应为了小热路径增益扩大生产搜索空间。

Deep dive 02

预算正确不等于请求正确。

Claude Code 的 1.1× premium 更新价格显示，代理错误路径修复避免某些请求重跑；SGLang 让可确定的格式偏差恢复为正确 tool call、让歧义情况 fail closed。这是同一控制面上的不同段落：账单、retry、解析、工具执行和最终结果必须能关联。

验证：按 request ID 记录 region、计费、HTTP 状态、retry reason、原始工具文本、改写规则和最终参数；再测 valid-call recall、误调用率和任务成功率。19 个 regression cases 不是生产成功率。

Deep dive 03

本期的证伪条件很具体。

若 #4593 的独立 E2E 测试不高于 1.0×或输出有回归，就把它降为单核信号；若 #4686 的真实 cache miss 让首请求节省小于预热成本，就不扩展 30 tactics；若任务级评测未显示 parser 修改提高 valid-call recall 而不升高误调用，就不把 #34237 写成 Agent 成功率提升。
