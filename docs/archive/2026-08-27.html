Executive readout

一个 fast path 至少要回答两件事：它的访问合法吗？它宣称完成时，硬件真的空闲吗？

本期五条一手 PR 把性能问题还原为运行时契约。SGLang 为 Hopper MXFP4 的非整齐 K 维补齐合法 scale 行，消除会随 allocator 触发的非法地址；vLLM 为 DP pause 加 device barrier，使控制面完成不再早于 GPU 空闲；TP autotune 则把每 rank 的随机 argmin 改为集体一致。FlashInfer 的稀疏注意力和 KDA 路线同时公布形状、硬件与 fallback 边界。所有数字均为 PR 作者报告。

30 秒结论 · 点击看详情

  1. 01Hopper MXFP4：sanitizer 66→0，coredump 3→0，吞吐保持中性。
  2. 02DP pause 的 future 只有在所有 worker device idle 后才能 resolve。
  3. 03TP autotune 20/20 tactic 分歧归零；cold tuning 付出 27 秒。
  4. 04MSA 的小 batch/长序列收益受 scratch、shape 与 proxy 主导比例约束。
  5. 05KDA prefill 的 2.57×–2.73×是 API GPU-time，不是服务吞吐。

推理框架与控制面

completion must be observable
vLLM #52914

“暂停完成”若没有 GPU fence，就只是一个错误的 API 承诺。

旧路径用 CPU `has_work()` 与 gloo all-reduce 决定 future；但 DP consensus 本身可启动未被 queue 追踪的 dummy batch。PR 让所有 worker 先 `synchronize_device()`，再 reset cache，最后 resolve future；wake-up 也补齐同步。生产复现中，pause 后紧接 RL weight sync/NCCL 的竞态才是材料风险，而非模型输出。

开发工具与 Agent

control-plane semantics are product semantics
运行时接口

控制面最危险的漏洞，是一个看起来成功、却允许硬件继续工作的 future。

vLLM 的 pause 修复把“调用者可以接管 GPU”写成了可测语义。相同原则适用于 agent 的停止、迁移、恢复与预算释放：API 需要定义时钟域、队列、worker 和 device 的全部完成条件；仅记录 controller return 并不能证明隔离已成立。

工程检查：为任何 stop/pause API 加一个 adversarial test：在 resolve 后立即提交互斥 GPU/NCCL 工作，并断言没有未完成 stream。

深挖 01

“完成”不是一个状态位，而是一条跨 rank、跨 stream 的证明链。

#52914 · #35343 · #18092

#52914 修复的不是普通空闲检测，而是 CPU control plane 与 GPU execution plane 的时间差：future resolve 前必须由所有 worker 过 device barrier。#35343 的 autotune 说明集体世界还有第二个问题：所有 rank 即使做相同次数的测量，也会因局部噪声落到不同 tactic。TensorRT-LLM #18092 同样将 host-tier 的 fallback 统一为 `KEEP_HOST`、`USE_NO_HOST` 或 `ABORT` 的世界 rank 结果。

深挖 02
