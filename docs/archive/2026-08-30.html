Executive readout

最危险的 fast path 不是“慢一点”，而是条件不成立时仍静默走下去。

今日三条 SGLang 事实落在同一条断层：ROCm 被错误的平台门控排除，只能正确但慢地运行；graph 容量外的 eager 回退复用旧 metadata，形状看似正常却越界；而音频模态只在一个 DP group 进入时，full-TP collective 可能让整服务等待 600 秒。FlashInfer 与 Codex 的新接口提供相反的工程范式：binding 不匹配或 sandbox 语义不可表示时，明确拒绝而非猜测。除 Codex release 外，性能与正确性数值均为 PR 作者报告；社区问题尚待确认。

算子与关键路径

measure local work and service consequence
FlashInfer #4722

all-gather matmul

可测事实：TP2/TP4 B300 cold-L2 geomean 分别1.083×/1.053×。prepared API 要求 K=8192、支持的 layout/group/world size；每次调用返回 fresh output storage，并对 changed binding 拒绝。

边界：4×GB300 Llama-70B、4096/32、C1 的真实服务仅1.00949×；当前不能把 microbenchmark 传导为高并发 SLA。

vLLM #45457

GPT-OSS MoE routing

雷达：复用 `SparseMatrix` top-k metadata，在 RTX5090 微基准每 MoE 层约少200μs、20→9 kernel、43.0%–43.6%。

为何落选：无服务 A/B，CUDA Graph 会摊薄部分 launch 成本；等待完整 request mix。

vLLM #54282

probabilistic draft sampling

雷达：draft/target 复用 Gumbel Philox offset 会扭曲 reject residual；以 salt 解耦。4×GB200 五模型 throughput −0.96%至+2.00%，acceptance 波动小。

边界：只影响非默认 `draft_sample_method="probabilistic"`，主要是分布正确性，不把跨零数据写成性能收益。

模型、模态与稀疏服务

all ranks must participate in the same contract
SGLang #37059 · 社区一手报告

audio encoder 的通信域不能与实际参与的 DP group 脱钩。

报告者在 MiMo-V2.5 的 TP8/DP2 配置下发现：audio encoder 的权重按 attention-TP=4 分片，却让 `RowParallelLinear` 在 full TP=8 reduce；带 audio 的 local batch 才会进入该 encoder。一个 group 加入、另一个缺席后，随后的 logits all-gather 只是排在已堵住的 collective 后面。两次独立复现为官方 FP8 weights 与 BF16 export，尚非维护者确认。

深度解读

comparison · deployment consequence · falsification
深挖 01

silent dispatch 的共同根因不是 kernel，而是门控条件没有进入可观测契约。

#36714 · #36915 · #37059

三个故障的表象不同：ROCm 是正确但慢，eager 是越界 fault，audio 是全服务 hang；共同点却是“平台、容量或模态”条件只存在于隐式路径选择。真正的目标不是再添一个 benchmark，而是让平台 predicate、capture miss、batch-local metadata、communicator participant set 都成为 request trace 的字段。

Codex 的治理面把“不确定”转为“拒绝或可审计”；推理 runtime 也应如此。

v0.151.0 不宣称更快，而是将 optional MCP 等待、tool-result interception、permission profile、executor path semantics 和 descendants budget 固化为接口与测试。与 #36714/#36915/#37059 的类比是本报推断：状态不再可安全解释时，不应静默继续。

最小复测清单

把门控故障变成发布前的实验矩阵。

固定 GPU/driver/model/TP/DP/EP、请求并发与输入模态；逐一注入 CUDA/HIP、graph hit/miss、audio presence、side stream 和 binding mutation。同步记录 route reason、q/kv shape、collective participant、fault/retry/restart、whole-step P50/P99 与 reference correctness。任何缺失此矩阵的速度数字，都只是一条候选线索。
