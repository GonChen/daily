Executive readout

fast path 的正确前提，是它看到的每 rank shape、并行拓扑和请求契约与生产状态一致。

SGLang 用真实 8,192-token scheduler buffer 替代 DP 的全局 32,768 上限，稳定并发段每芯片 TPS 增加约 5%–7%。vLLM 的 DeepSeek V4 MoE-EP 后端把 SM100、NVSHMEM、EPLB 与 capture 变成显式 gate；同一日又在 TP 下关闭非确定性 fusion，让八次相同推理收敛为一个 bit-exact 输出。Fast path 不是“硬件支持”的同义词：不匹配时应回退或拒绝，而非静默继续。

开发工具与 Agent

request contract is a product surface
从 CLI 到服务端

fast path 的 UX 不是“尽量接受”，而是让调用方知道哪些承诺无法履行。

TensorRT-LLM 不再用错误的 distribution 静默回答不可支持的 sampling request；vLLM 的 batch invariance 让用户用吞吐交换 bit-exact；FlashInfer 将 LSE 需求变成显式参数。这些不是同一 API，但都是同一控制面原则：正确性参数、返回类型和 fallback 必须可见、可测、可审计。

宏观问题

深挖 01

全局上限不能混入局部 fast path。

#36219 · #49636 · #35505

#36219 用 DP 每 rank 8,192 token 替换全局 32,768，C4–64 便得到 +4.94%–6.77%。#49636 显示 MoE kernel 的 crossover 又受 tokens/rank 影响；#35505 则明确 EP 缺 slot 就不能 fusion。三条事实共同反驳“只要启用加速库就会更快”的假设。

深挖 02

性能 API 也要签正确性契约。

#51292 的 TP fusion、#4502 的 `return_lse` 默认与 TensorRT-LLM #17955 的 speculative admission 同向：框架不应在无法履行请求时暗中改变语义。

契约旧行为新行为
batch invariance8 个 bit-exact 输出回退至 1 个输出
LSE默认要求依赖调用方显式请求
sampling丢约束仍返回admission 拒绝

部署动作：把 invariant 服务与普通服务分池；升级 attention 时为 LSE consumer 增加兼容性测试；观察 speculative 拒绝率与 fallback。证伪：若 deterministic path 在更大 TP 仍不 bit-exact，或 LSE/拒绝路径的集成测试暴露兼容故障，当前 guard 不完整。
