模型、投机与稀疏选择

correctness is not the same as a valid-shaped output
SGLang #36807 · 社区报告

当 top-k 只检查范围、形状和去重时，候选 truncation 可以成为静默的模型行为变化。

报告称 DeepSeek V3.2 DSA 的 k=2048 unfused/miss-JIT path 可能进入 fixed candidate buffer。B200 对照显示64K columns 为0/64错，256K为64/64错，1M为64/64错且错误更多；输出看似合法。该报告的价值是把 score multiset 与 `torch.topk` 做 tie-robust 比对，而不只是检查 index 格式。

4,096CUDA candidate capacity
4,178–4,448256K threshold-bucket population
6–42每错行非 true-top-k 选择

行动：在维护者确认前，对长 row/k=2048 的受影响 route 做 reference sampling 或 fail-closed；不要把 issue 当成已修复漏洞，也不要仅凭 valid indices 断言稀疏选择正确。

开发工具与 Agent

observability is part of safety
工程准则

异步 API 不应只暴露“完成”，还应暴露资源和顺序是否满足其前提。

#36657 与 #53333 的共同点是：一个重叠路径要先声明自己会占用什么资源、什么时候能与另一个 stream 并行。为 connector、cache 和 agent 的后台任务提供 `reason`、`ordering`、`fallback` 与 `resource reservation` 观测，才可将“偶发 hang”还原为可行动条件。

最小测试：并发提交一个故意占用资源的 side stream 与一个需要全局进度的路径；再分别注入 sync、async、mixed 数据依赖，断言 route、返回时间和输出正确性。

深度解读

comparison · deployment consequence · falsification
深挖 01

重叠不是免费并行：它是一份资源驻留与执行顺序的合同。

#36657 · #53333

#36657 的失败来自 grid barrier 等待永远无法 resident 的 cluster；#53333 的收益来自 host 不再在 forward 前同步构造 async load descriptor。二者都不是“多开线程”或“后移调用”即可成立，而是需要明确何时保留资源、何时推迟提交、何时必须走保守路径。

路径 旧的隐含假设 新 gate 可观测结果
MegaMoE 所有 SM 可用且 cluster 总能 resident SM100+ reserve 2 / even count side-stream repro 从 timeout 到完成
KV load 所有 load 都应 pre-forward 仅 async-only post-forward TPOT −4.92%，TTFT +0.07%

动作：把 SM reserve、side-stream occupancy、sync/async/mixed classification 和 connector completion 写入同一条 request trace。证伪：若 reserve 增大在真实 workload 降低吞吐，或 mixed load 后移仍正确且更快，现有 gate 需要重新测量。

深挖 02

fast path 的选择器必须同时处理“看不见的状态”和“容不下的候选”。

#36094 用 capture-time scalar 选择 split-K，放弃不可见 token-K 的最优值以保证 graph 安全。#54168 用 M=5 作 SIMT/WGMMA 分界。#36807 的 fixed candidate buffer 则显示 bounds guard 可能悄悄截断真正需要比较的集合。

选择器 已知条件 安全边界 反例
MI355X split-K capture scalars 3.7% residual regret plain TP8 无稳定收益

动作：将 route/threshold 与 reference sampling 绑定，特别是长 row 和稀疏候选。证伪：维护者若复现不了 #36807，或 JIT 默认路径不可能进入该 AOT kernel，应缩小影响范围；在此之前它仍是待验证社区信号。
