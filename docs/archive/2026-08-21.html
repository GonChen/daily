新的容量合同，开始像推理服务的 admission control

IRAS 不等于“数据中心不能接入”，也不适用于已有容量或自带新增资源的客户。它把谁支付、谁提供资源、谁在紧急状态让渡负载写进准入规则。

部署含义：对 24×7 推理业务，要把电力中断条款纳入多区域路由、柴油/储能持续时间、模型降级与客户 SLA 设计。

01｜NVIDIA Ohio 担保：供给商开始出售“可融资的算力工厂”

8‑K 的关键不是“$105B 投资”。文件写的是 residual‑value guarantees：首期约 4.25 IT‑GW 的每份租约在 ready‑for‑service 后才生效；若租户违约，NVIDIA 再按约定短缺额、再出租或出售等路径承担责任。OpenAI 仍是租户并承诺补偿实际支付。

编辑推断：这让稀缺资源从 GPU/HBM 扩展到土地、电力和壳体，并将供应商信用纳入项目融资。但单笔上限不等于净现金暴露，也不能被直接计为收入。部署侧应把“担保方、开工条件、投运节奏、备用容量、租户信用”同 token 成本放在一张风险表里。

验收链：IT‑GW → 并网/壳体 ready‑for‑service → 租约承诺 → 担保触发条件 → 利用率与续代 → 现金/信用风险。

02｜长驻 agent 的价值不在“自动”，而在可唤醒、可暂停、可归责

Cursor 让 cloud agent 订阅 PR、Slack 和计划任务，DeepSeek Harness RC.8 把 /goal、图像、子代理 bundle 和并发检索塞进统一 runtime；Claude Code 同期加入一次性 idle 通知。它们共同把 agent 从交互式 CLI 推向事件驱动服务。

工程边界随之扩大：订阅应有幂等键，唤醒必须受预算与权限范围约束，子机需要可审计的环境与成果回传；“agent 修了 CI”也不能推导为可自动合并。运行时的队列、状态、凭据和人工升级路径，才是可靠性的主语。

生产门槛：事件来源 → 去重/限流 → 权限与预算 → 隔离执行 → 可观测状态 → 人工审批/回滚。

03｜推测解码的零气泡：最快的路径也必须说明精度与适用硬件

SGLang #35570 为 NPU 加入 SGLANG_SPEC_V2_ZERO_BUBBLE 并调整 draft worker 和 token metadata 的传输；#35572 只扩充了 NPU batch matmul‑transpose 的 autotune 候选。其 PR 模板中的 accuracy 与 speed 结果均未填，因此今天能确认的是“接口与路径合入”，不是快多少。

这恰好是推理系统的正确阅读法：先分辨它优化的是 H2D 元数据、draft/verify 排程、kernel 选择还是端到端 goodput；再看 model、长度、batch、精度、NPU 型号、acceptance rate 和 P99。没有这些，zero‑bubble 是方向，不是 benchmark。

验收链：acceptance rate → draft/verify overlap → H2D/collective → TTFT/P99 → output goodput → 数值/任务正确性。
