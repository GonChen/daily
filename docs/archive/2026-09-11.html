Executive readout

快路径真正的产品定义，是它在什么条件下被允许命中、何时必须退回。

SGLang、vLLM 与 FlashInfer 的三条性能提交都给出正向数据，也都把收益锁在特定硬件、拓扑、shape 或 backend 选择上。不能只复制最大百分比：DSpark 的 +12.15% 排除 prefill 且模拟 acceptance；MI350 的 FP8 GEMM 在 DPA 与 EP 路由差异很大；B200/B300 的 KDA 仍默认保留 CuTe DSL。DeepSeek Harness 的预发布把相同原则延伸到 Agent 状态与代理继承；社区报告则提醒，量化 draft 可能静默失去投机价值而不影响表面输出。

local saving is not an SLA
vLLM #51692

FP8 o-proj

可测事实：8×MI350、1k/1k、DeepSeek-V3，TP8+DPA 的并发1–128 QPS 分别提高4.61%–8.14%；TP8+EP 从-0.39%到+9.01%。GSM8K flexible exact 0.9477，nightly 0.9439。

FlashInfer #4967

fused KDA

可测事实：所有官方 subset row 快于 CuTe DSL，B200/B300 geometric mean 约1.05×；source/export 的整体几何均值差低于0.5%。

边界：组合表部分继承未变 kernel 的旧量测；设定显式 mode、默认 backend 与每个 state-index route 才能复核。

TensorRT-LLM #18541

KVCM2 resize

雷达：long-sequence burst resize 使用 LDGSTS 或 `cuMemcpyBatchAsync`，并让 background resize 与只读 reuse probe 共享/独占锁；78 C++ 与220 Python test pass。

为何未进 Top5：无服务 A/B 或 latency 数字。验证成功不等于兑现了 resize/尾延迟收益。

模型、量化与投机服务

functional correctness can hide capacity loss
SGLang #39087 · 社区一手报告

投机 drafter 的最低可观测指标不是“能否出答案”，而是 accept length。

报告者在同一 target 下比较两份架构与 selector 配置相同的 DFlash2：compressed-tensors arm 的422个 decode batch 中 accept len 1.03、accept rate 0.004、约38 tok/s；BF16 arm 的100个 batch 为3.71、0.61、约171 tok/s。量化版没有显性错误，功能测试也通过；verify 拒绝错误 draft，所以质量表象可保持正常，但额外 verify 让性能低于无 drafter。

行动：在量化 speculative draft 上采集 accept length/rate、token/s 与 no-drafter 基线；在上游确认前以 warning/禁用策略管理风险，而不是把 issue 视为已修复事实。

成本提示

未命中快路径是供给损失。

一次 silent fallback 或低 acceptance 不一定形成 crash，却会抬高每 token 成本、压缩高峰冗余。运营指标要收集 route hit、拒绝原因、acceptance 和 P99，而不只看平均 kernel time。

深度解读

comparison · deployment consequence · falsification
深挖 01

性能主张的最小可信单位是“条件化路径”，不是一个加速百分比。

#39068 · #51692 · #4967

三条 PR 都在做相似的工程事：减少关键路径的工作。但它们的可信单位不同。DSpark 的数字只覆盖 GB300、TP4/EP4、BS1、固定 I/O 和模拟 acceptance；ROCm FP8 在 DPA 与 EP 下给出不同区间；KDA Cake 只在指定 GPU 和 state-index mode 下被选择。将其中任一局部比例直接写成“模型更快”或“平台更快”，都会丢失决定部署价值的变量。

路径正向信号决定能否外推的条件最小下一步
DSpark verify761.03→853.49 tok/s模拟 acceptance、无 prefill、GB300/BS1自然 acceptance 与 request mix A/B
ROCm FP8DPA +4.61%–8.14%DPA/EP、tuned shapes、env gate按 route 报 P50/P99 与命中率
KDA CakeB200/B300 ≈1.05×state-index、backend selection、默认 fallback生产 backend share 与端到端 SLA

证伪：若相同 request mix 下的 whole-service A/B 不显示趋势，或快路径在未列出的 route 上回退/失真，则这些局部收益不能支持推广。页面没有声称独立复现。

深挖 02

Agent runtime 与推理 runtime 的共同职责：无法证明状态仍适用时，不应静默延续。

Harness RC 将代理 queue、Steer、session 生命周期、system prompt/KV cache 与 proxy 环境显式化。与推理 fast path 的类比是编辑判断，而非 release 的性能结论：当 binding、input shape、session ownership 或网络条件变动时，系统需要可见的 route/拒绝/恢复语义。

状态应有契约应测信号
子代理消息queue、edit、Steer、stop 的顺序投递、取消、恢复成功率
system prompt模型明确声明能否保持 KV cachecache hit、输出一致性、fallback
网络代理启动环境变量的继承和 bypass每次请求的代理选择与失败原因

限制：RC 不等于稳定接口；本期 pi 连接错误未被归因到 proxy，也不构成对 Harness 的反证。

最小复测清单

让快路径在上线前先经历一次反向测试。

固定硬件/driver/model/TP/EP、I/O、并发和环境变量；同时跑 enabled、forced fallback 与 no-optimization 三臂。记录 TTFT/TPOT/P99、acceptance、route reason、错误/重启和质量基线。对 agent 还要注入队列编辑、Steer、stop、session 升级及代理 bypass。任何只给局部 kernel 或单路径平均值的提交，都先进入雷达而非容量预测。
