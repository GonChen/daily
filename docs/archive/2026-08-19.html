Executive readout

AI 推理的下一次提速，不在“再快一点 kernel”，而在让并行、缓存、工具调用和电网都遵守同一套准入规则。

vLLM 为 DeepSeek V3.2 接入 PCP 后，在 B300 的 32k prefill 特定测试中，把 p50 从 973.9ms 降至 366.9ms（2.65×）；代价是切 sequence shard 后，仍必须在写入复制的 KV cache 前聚合 kv_c、k_pe 与 indexer key。SGLang 的 Kimi‑K3 修复揭示另一种“准入”：tool_choice=required 与 response_format 同时出现原本不可满足，却只会悄悄丢约束或丢工具调用。基础设施端，PJM 提议在供电危险时优先削减没有自带新增容量的新数据中心负载。今天的共同问题不是把系统推到极限，而是先说清谁可以占用哪一种稀缺资源、谁来承担失败。

编辑推断

新的容量合同，开始像推理服务的 admission control

IRAS 不等于“数据中心不能接入”，也不适用于已有容量或自带新增资源的客户。它把谁支付、谁提供资源、谁在紧急状态让渡负载写进准入规则。

部署含义：对 24×7 推理业务，要把电力中断条款纳入多区域路由、柴油/储能持续时间、模型降级与客户 SLA 设计。

Blackwell 推理优化同时推进快路径与安全回退

TensorRT‑LLM 的 DSpark 融合只在 SM100/SM103 启用，其他硬件保留 PyTorch fallback；同一批主线改动还为 KV cache rebalance 补齐 TP、CP、PP 与 attention‑DP 下的协调逻辑。

01｜PCP 的 2.65×：把并行从算力切分变成 cache 协议

TP 的 head shard 在 sparse‑MLA/indexer 上未必是最省时的。vLLM 的 PCP 改为 shard sequence，因此 32k prefill profile 获得 2.65× p50；但 KV cache 仍保持像 TP 一样复制，前向新生成的 kv_c、k_pe、indexer key 必须先 gather 再插入 cache。

这不是实现细节，而是性能边界：一旦跨请求 prefix reuse、PD 分离或故障恢复进入路径，谁持有哪段 cache、何时合并、何时可见，就决定优化能不能生产化。PCP 数字只对应 B300、GLM‑5.2 NVFP4、32k prefill 和该 PR 叠加状态；不能外推到 decode 或所有模型。

验收链：prefill p50/P99 → cache 写入与命中 → 跨 rank 通信 → PD/重启恢复 → decode goodput。不要只收集 prefill benchmark。

02｜agent 的可靠性，是服务协议是否允许失败被看见

SGLang 的 Kimi‑K3 修复很具体：约束冲突原本会悄悄丢 tool constraint，thinking 中提前吐出的 tool 会变成 reasoning，截断 tool 在流结束时直接消失。把不可满足的 required + response_format 改成 400、把截断改成告警，是比“再提高工具调用率”更基础的改进。

DeepSeek Harness RC.7 的持久图片、Job Panel 与 low reasoning，又把这条链延伸到 agent runtime。用户真正需要的不是一次漂亮的 demo，而是可观察的工具 schema、可恢复的附件和可审计的子任务状态。

生产门槛：工具约束冲突显式失败 → 流截断可观测 → 角色/附件可持久化 → 子任务有生命周期 → 成本/推理强度可控。

03｜电网开始为 AI 工厂设计 admission control

PJM 的 IRAS 提案不是简单的“限制数据中心”。它尝试给没有新增供给支持的 Large Load 加上紧急时优先削减的秩序，以保护既有用户。对数据中心而言，容量合同的产品形态因此发生变化：同样的 MW 可能带有完全不同的可靠性和停机尾部风险。

这与推理系统的 admission control 异常相似：不能承诺就该排队、限流或拒绝，而不是静默挤压已有用户。区域选择、储能/自备电、可中断合同与模型降级策略，应由设施、财务和服务团队共同设计。

规划清单：合约容量 → 自带新增资源 → 可中断条款 → 备用持续时间 → 跨区容量 → 服务降级等级 → 客户 SLA。
